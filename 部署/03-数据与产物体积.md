# 数据与产物体积策略（部署数据包）

公网部署最容易踩的坑不是代码，而是**数据**：本地跑得好好的，云端打开全是 0。
这份文档说明本产品怎么在「仓库尽量小」和「指标不变」之间取平衡，以及怎么自己验证。

---

## 1. 机制：parquet 优先，CSV 可选

`services/data_store.py::_read()` 的取数顺序：

```python
pq = FEATURES_DIR / (path.stem + ".parquet")
fresh_pq = pq.exists() and (not path.exists() or pq.stat().st_mtime >= path.stat().st_mtime)
if parquet_fallback and fresh_pq:
    return pd.read_parquet(pq, columns=usecols)     # ① 有 parquet 且不比 CSV 旧 → 直接读
if not path.exists():
    return pd.DataFrame()                            # ② 两者都没有 → 空表（页面给出空态，不报错）
df = pd.read_csv(path, **kw)                         # ③ 只有 CSV → 读 CSV 并回写 parquet
```

结论：

- **只提交 `data/features/*.parquet` 也能完整运行**（这是云端采用的方式）；
- 有 CSV 时按修改时间取更新的那份，本地开发行为不变；
- `data/processed/*.csv`（≈ 38 MB）属于「可从 raw 重跑再生的中间产物」，不需要入库。

## 3. 怎么自己验证「没有 processed CSV 也能跑」

最直接的做法是把三个大 CSV 暂时移开，跑一次应用级测试，再放回去：

```bash
cd 产品实现
mkdir -p /tmp/csv_bak
for f in comments_cleaned comments_clustered sentiment_results; do
  mv "data/processed/$f.csv" "/tmp/csv_bak/$f.csv"
done

./vene/bin/python - <<'PY'
from services.data_store import store
from services.features import kpi_summary
ds = store()
for name in ("raw", "cleaned", "clustered", "sentiment"):
    df = getattr(ds, name)(); print(name, len(df))
print(kpi_summary())          # 应与本地一致：n_raw=51224, n_kept=34426
PY

# 还原
for f in comments_cleaned comments_clustered sentiment_results; do
  mv "/tmp/csv_bak/$f.csv" "data/processed/$f.csv"
done
```

本仓库最近一次实测结果（2026-09-29）：

```
raw 51224 / cleaned 48583 / clustered 48583 / sentiment 46459
KPI: n_raw=51224  n_kept=34426  mean_sentiment=0.4632
AppTest（属性情感分析 / 数据管理 / 洞察与报告 / 决策总览）：
  exc=0  render_error=None  TOTAL_BAD = 0
```

即：**没有 processed CSV 时，六个视图照常渲染，指标与本地一致。**

## 4. 数据包维护命令

```bash
cd 产品实现

# 体检：体积、行数、缺失项
./vene/bin/python 部署/prepare_public_data.py

# 重建：从 data/processed/*.csv 重新生成 5 个 parquet（改过流水线后执行）
./vene/bin/python 部署/prepare_public_data.py --build

# 模拟云端布局：parquet 已在位时删掉 processed CSV，验证完再决定是否保留
./vene/bin/python 部署/prepare_public_data.py --prune-csv          # 先看会删什么
./vene/bin/python 部署/prepare_public_data.py --prune-csv --yes    # 确认删除
# 恢复：把 data/raw/comments_raw.csv 放回，数据管理 → 三阶段执行器 重跑即可再生
```

## 5. 三个可选的取舍方向

| 想达到的效果 | 做法 | 代价 |
|---|---|---|
| **仓库更小**（< 3 MB） | 删掉 `data/raw/comments_raw.csv`，只留 parquet | 数据管理页的「数据质量 / 字段字典 / 导入」会变成空态 |
| **缩小演示数据量**（例如只保留 5,000 条评论） | 本地从 raw 抽样 → 重跑三阶段流水线 → `prepare_public_data.py --build` → 提交新 parquet | 与论文基准并列时的实时偏差数值会变（论文校准口径本身不变） |
| **提交全量中间产物**（不推荐，仅在需要线上重跑流水线时） | 把 `.gitignore` 里 `data/processed/*.csv` 注释掉，`git add data/processed` | 仓库 +38 MB，克隆与构建变慢 |

单文件超过 100 MB 时改用 [Git LFS](https://git-lfs.com/)：

```bash
git lfs install
git lfs track "data/**/*.parquet"
git add .gitattributes && git commit -m "chore: parquet 走 LFS"
```
（Streamlit Community Cloud 会正常拉取 LFS 指针指向的对象；Render/Railway 需确认构建环境已装 git-lfs。）
