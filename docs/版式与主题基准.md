# 版式与主题基准（Phase 2.1 · 视觉一致性改造）

> 本文件解释"为什么这样改版"。所有结论均有外部来源，改动落在 `ui/layout.py` 与 `ui/theme.py`。

## 一、参照的市面基准

| 来源 | 采纳的规则 | 落点 |
|---|---|---|
| [NHS England Data Viz CoP — Layout](https://nhsengland.github.io/data-viz-community-of-practice/dashboard_design/layout/) | 页面四周 32px 留白；卡片内 16px 内边距；卡片之间 32px 间距；页头**左侧标题+副题、右侧状态信息**（左右分栏，右侧固定窄栏）；一排最多 6 个 KPI；正文图表数据多时用通栏卡片；避免双滚动条 | `theme._STRUCTURE`：主区 `padding: 16px 32px 48px`、面板内边距 16px；`.ds-topbar` 左标题右徽章；`kpi_row` ≤6 卡 |
| [Shilp Sutra — Spacing（三档节奏）](https://unpkg.com/@devalok/shilp-sutra@0.54.0/make-kit/foundations/spacing.md) | 只用三档：**8px 相关 / 16px 分组 / 32px 区块**，不要五档并用（"三档成节奏，五档成噪音"） | CSS 变量 `--gap-s:8px / --gap-m:16px / --gap-l:32px`；垂直块间距 16px；区块标题上边距 32px |
| [SAP Fiori — Semantic page layout](https://www.sap.com/design-system/fiori-design-web/v1-136/page-types/page-layouts/semantic-page/usage/#1) | 页面是"语义页壳"：固定头部 + 页头 + 内容区，各区块职责单一、可复用 | `app.py` 顶栏（`.ds-topbar`）+ `layout.page_head()`/`section_header()` 的三段式；视图只声明自己的内容层 |
| [NHS — 导航与页头 Tips](https://nhsengland.github.io/data-viz-community-of-practice/dashboard_design/layout/#header) | 导航只用一种控件（不要图标+文字混用两套）；页头避免塞满图标 | 侧栏只保留单一 `option_menu` 导航；页头只放口径徽章 + 数据新鲜度 + 筛选结果 |

由此得到的四层结构（所有视图统一）：

```
页头    .ds-topbar            ← app.py，全站唯一（视图名 + 口径/数据/筛选徽章）
区块    section_header         ← 一个"章节"一次（标题 + 副题 + 42px 色条）
卡片面  layout.panel(...)      ← 统一 border 卡片，卡内只谈这一个话题
内容    图 / 表 / KPI 行        ← 高度只取 150/260/340/440 四档
```

## 二、栅格：为什么禁止随手写比例

改造前 5 个视图出现了 **15 种**不同的 `st.columns` 比例（`[4,1,1,1]`、`[4.2,1.2]`、`[1.55,1]`、`[1.15,1]`、`[1.35,1]`、`[1.2,1,2.2]`、`[3,2]`…），肉眼可见地"飘"。现在收敛成 `ui/layout.py` 的 9 组具名比例：

| 名称 | 比例 | 用途 |
|---|---|---|
| `head_action` / `head_actions` | 4:1 / 4:1:1:1 | 区块标题 + 操作按钮 |
| `title_badges` | 1.2:3 | 页头标题 + 右侧徽章条 |
| `main_rail` | 1.6:1 | 主内容 + 右侧结论栏（看板主骨架） |
| `control_canvas` | 1:2.6 | 左参数 + 右结果 |
| `rail_canvas_rail` | 0.9:3:0.9 | 对称三栏：结论型内容的控制/画布/结论 |
| `console_canvas_result` | 1.3:3:0.9 | 宽控制台 + 画布 + 结论栏（模拟器参数表单需要宽度） |
| `even` / `even3` | 1:1 / 1:1:1 | 等分 |

`split()` 对未知名字直接抛错，从机制上阻止版式回退。

## 三、明暗主题的完整性

改造前只换了自己的 CSS 变量，**Streamlit 内建组件（表格、代码、滑块、单选、进度条、输入框）仍停在默认浅色**，所以"切了深色但没切全"。现在：

1. `theme.sync(mode)` 在每次运行早期写回 Streamlit 主题配置（`theme.base / primaryColor / backgroundColor / secondaryBackgroundColor / textColor`），内建表格与代码块按令牌渲染；
2. `:root` 直接覆盖 Streamlit 的 `--primary-color / --background-color / --secondary-background-color / --text-color`，使**滑块、单选、复选、开关、进度条、Tab** 在不刷新页面的情况下立即跟随；
3. 徽章、KPI、面板的颜色全部来自随模式变化的令牌（新增 `brand_fg / ok_fg / warn_fg / bad_fg / muted_fg`），浅色下不再出现"浅色文字贴白底"的低对比；
4. Plotly（`theme.finish`）、ECharts（`echarts_theme`）在同一令牌下出图，三套渲染引擎不再各说各话。

### 首屏顶部：一条空白横条 + 侧栏收起后打不开（两个连带 bug 的根因）

Streamlit 的 `stHeader` 在源码里是 `position: absolute; top: 0; left: 0; right: 0` 的**覆盖层**
（`StyledHeader`），块容器 `stMainBlockContainer` 默认用 `padding-top: 6rem` 给它让位；
`stHeader` → `stToolbar` 里放着**侧栏折叠/展开按钮（悬停显隐）**、⋮ 主菜单与 Deploy 按钮。
改造中踩了两处：

1. 先把主区 padding 压到 `16px`（首屏顶进顶栏），又把顶栏写成 `88% 透明 + backdrop-filter: blur(10px)` 
   → 顶栏变成一条"毛玻璃"，压住首屏标题；
2. 又为了去掉 Deploy 按钮写了 `[data-testid="stToolbar"] { display: none }` 
   → 整条工具条被隐藏，**侧栏收起后 `stExpandSidebarButton` 尺寸归零、点不到**，侧栏再也打不开。

正确做法（三步，缺一不可）：

1. 顶栏只改外观：`background: transparent; backdrop-filter: none; border-bottom: none`，**不覆盖 `pointer-events`**，让侧栏开关与 ⋮ 保持可点；
2. 主区顶部不再为它留白：`padding: 12px 32px 48px`（顶栏透明后不需要 56px 让位）；
3. 工具条**保留**，只隐藏本地演示无意义的 Deploy：`[data-testid="stAppDeployButton"] { display: none !important; }`，
   并给 `.ds-topbar` 右侧留 56px，避免徽章被 ⋮ 压住。

> 验收方式（可复现）：headless Chrome + CDP 量 DOM —— `stHeader` 背景为 `rgba(0,0,0,0)`、
> `stMainBlockContainer` 的 `padding-top` 为 `12px`、`.ds-topbar` 顶部落在 28px（无空白横条）；
> 收起侧栏后 `stExpandSidebarButton` 有真实尺寸（28×28）且点击后侧栏宽度回到 256px。
> 脚本见 `_shots/verify_final.py`（开发期工具，已 gitignore）。

## 四、验收口径
